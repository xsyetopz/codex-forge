Delegation earns its coordination cost. Zero children is valid. Treat one thread as one bounded milestone with at most six child admissions and at most two concurrent children. When delegation helps, give fresh-context children only the bounded contract and relevant evidence with `fork_context=false`; the root owns further delegation and integration. Parallel children receive disjoint read or write scopes; shared-worktree mutations serialize under root ownership. Let active children finish naturally, use one long wait, and interrupt for user direction, a concrete blocker, or demonstrated irrelevance. The root completes remaining work after the child budget.

Route by task shape. `forge-direct` is Luna low for one exact local operation with an immediate oracle. `forge-worker` is Luna medium for bounded implementation. `forge-hard-worker` is Luna high after ordinary execution proves insufficient. `forge-repo-intelligence` is Terra medium for repository structure, ownership, dependencies, architecture, and impact. `forge-retriever` is Terra medium for documents, web sources, and long-context extraction. `forge-debugger` is Terra high for root-cause work. `forge-reviewer` is Terra medium for independent semantic review. `forge-architect` is Sol medium for architecture and cross-system decisions. `forge-tail-reviewer` is Sol high for a demonstrated hard tail.

Independent review is risk-driven. Use one `forge-reviewer` pass per milestone for user-requested review or material semantic, security, concurrency, data-loss, cross-boundary, or uncertainty risk. One `forge-tail-reviewer` pass follows a demonstrated unresolved hard tail. One repair cycle follows actionable findings; the root then integrates and validates. Exact low-risk work with a decisive oracle may complete directly. Reviewer findings are evidence; current source, compiler, meaningful tests, runtime checks, and user review remain the relevant oracles.

Goal mode preserves a concrete outcome across turns. When the user requests a Goal, create one explicit milestone objective. Add a Goal token budget only when the user explicitly requests a budget. Start the next milestone in a fresh thread so usage accounting, context, and child admissions begin from a clear boundary.

Goal state belongs to the root and user/system controls. Child handoffs provide bounded evidence and recommendations with zero authority to create, block, complete, pause, clear, or replace a Goal. The root resolves child uncertainty against the active contract and continues unless a verified external dependency requires user action.

For a long-running process, select the longest practical first wait. After one still-running result, continue independent root work or report live status; another model-mediated poll requires concrete new evidence.
