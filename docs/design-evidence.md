# Design evidence

This document records the external evidence used for current Forge design choices. It isn't injected into every agent turn.

## Adopted principles

- Define observable acceptance criteria and implementation boundaries before mutation. Specifications capture intent and constraints; code and tests remain the executable result. Sources: [Spec Kit](https://github.com/github/spec-kit), [How to write a good spec for AI agents](https://addyosmani.com/blog/good-spec/), and [Structured-Prompt-Driven Development](https://martinfowler.com/articles/structured-prompt-driven/).
- Keep prompts reviewable and focused, but place enforceable state transitions in deterministic tools. The TDD-governance paper separates model proposals from validation and mutation authority and emphasizes bounded repair; it also reports that prompt-level enforcement remains incomplete. Source: [TDD Governance for Multi-Agent Code Generation via Prompt Engineering](https://arxiv.org/abs/2604.26615).
- Use graph-derived change impact to choose relevant tests, and treat regression rate as a first-class result. The cited TDAD evaluation reports improvements on two local models and a bounded SWE-bench sample; Forge adopts the mechanism, not a universal performance claim. Source: [TDAD: Test-Driven Agentic Development](https://arxiv.org/abs/2603.17973).
- Keep skill entrypoints concise and link conditional detail directly where a branch needs it. The portable specification defines progressive disclosure, focused one-level references, optional scripts and assets, a 500-line entrypoint recommendation, and the complete frontmatter field set. Sources: [Agent Skills specification](https://agentskills.io/specification) and [OpenAI Build skills](https://developers.openai.com/plugins/build/skills).
- Treat Codex hooks as deterministic lifecycle handlers with runtime-provided JSON input. Scope matchers to canonical tool aliases, cap model-visible context, and preserve manual hash-based trust review for plugin hooks. Source: [OpenAI Codex Hooks](https://learn.chatgpt.com/docs/hooks).
- Use summary-backed compaction for unattended task continuity. Codex CLI 0.149.1's token-budget path explicitly skips summarization and creates a fresh context window, so Forge leaves that feature unset until a durable checkpoint service is present and verified. Sources: [standard compaction](https://github.com/openai/codex/blob/rust-v0.149.1/codex-rs/core/src/compact.rs#L111-L140), [token-budget compaction](https://github.com/openai/codex/blob/rust-v0.149.1/codex-rs/core/src/compact_token_budget.rs#L21-L25), and the [recorded Forge findings](context-compaction-2026-08-24.md).
- Leave `features.multi_agent_v2` unset. The flag is stable and default-off; enabling it globally forces V2 for every model. V2’s default spawn schema hides model overrides, omitted `fork_turns` becomes a full-history fork, and ChatGPT-auth reserved schemas reject a client-side unhide. Forge installs a pinned complete `model_catalog_json` that restamps Sol/Terra/Luna to V1 and `use_responses_lite = false`, and keeps registered V1 roles with `fork_context=false`. The catalog is a full replace; a one-field Lite patch fails startup. Sources: [openai/codex#32031](https://github.com/openai/codex/issues/32031), [openai/codex#38355](https://github.com/openai/codex/issues/38355), and the [model-instruction audit](model-instruction-audit-2026-08-24.md).
- Set `agents.max_concurrent_threads_per_session = 8` as the runtime capacity ceiling. Current Codex documentation says the field caps concurrently open spawned-agent threads excluding the primary, and that Codex closes completed agent threads as part of orchestration. Forge guidance therefore keeps the active set smaller by default: 2-4 for ordinary independent work and expansion toward 5-8 for genuinely independent read-heavy or mechanically sharded work. Sources: [Codex subagents](https://developers.openai.com/codex/agent-configuration/subagents) and the [model-instruction audit](model-instruction-audit-2026-08-24.md).
- Route registered Forge roles by task shape: Luna for clear, repeatable, high-volume execution; Terra for balanced retrieval and read-heavy analysis; Sol for complex, ambiguous, architecture, debugging, and semantic-review work. The current role TOML files own those model selections; root guidance prefers registered roles over raw model overrides. Source: [Codex model selection](https://developers.openai.com/codex/models).
- Make the routing boundary observable: Luna requires an explicit contract, local blast radius, decisive oracle, and cheap rollback; ambiguous requirements, cross-system changes, and semantic review that reconstructs intent route to Sol roles. The 2026-08-27 supplied Reddit capture is observational evidence for this safeguard, not a model-quality or quota guarantee.
- Start ordinary Forge work at medium effort, use Luna low for bounded scouting, and reserve xhigh for explicit hard-tail roles. Higher effort is an escalation after a concrete lower-effort failure, which limits reasoning loops and subscription quota spikes without treating community usage reports as a fixed cost model. Source: supplied `codex-subscription-model-effort-guide.md`.
- Bun's Rust rewrite supplies a bounded concurrency lesson rather than a universal performance claim: it used disjoint test-file shards and a repeated unit of one implementer, two adversarial reviewers, and one fixer, while large integration, disk, process, and socket workloads required stronger isolation. Forge applies the narrower lesson by reserving extra lanes for independent shards, serializing shared-write or dependency overlap, and keeping expensive validation/I/O bottlenecks bounded. Source: [Rewriting Bun in Rust](https://bun.com/blog/bun-in-rust).
- Replace stock `default.md` through `model_instructions_file`. Additive `developer_instructions` and repository `AGENTS.md` cannot cancel system-identity clauses (preamble, friendliness, ambition). Children inherit the parent session’s effective base instructions; a role-local `model_instructions_file` is accepted in TOML then silently dropped. Sources: [openai/codex#40042](https://github.com/openai/codex/issues/40042) and the [model-instruction audit](model-instruction-audit-2026-08-24.md).
- Keep the replacement lean, positive-phrasing, and ordered Role → Goal → Success → Constraints → Tools → Output → Stop, without section labels. User requirements and their stated order occupy the Goal slot before execution guidance. Word count and SHA-256 are pinned in `tests/unit/repository-contracts.test.mjs` (currently 245 words). Source: [GPT-5.6 Sol prompting guidance](https://developers.openai.com/api/docs/guides/prompt-guidance-gpt-5p6).
- State each instruction-layer rule once. A single observed failure does not authorize a wider prompt policy. The PCSX2 check-before-use inversion stayed four words (“and their stated order”); a flags-from-docs / check-docs-before-every-binary rule was rejected. Record the observation, map the failure, then change the smallest Goal-slot wording. Sources: the [observational evidence synthesis](observational-evidence-2026-08-22.md) and the [model-instruction audit](model-instruction-audit-2026-08-24.md).
- Use Bun's built-in TOML and YAML parsers for repository runnables instead of adding runtime package dependencies. Sources: [Bun TOML.parse](https://bun.com/reference/bun/TOML/parse) and [Bun YAML](https://bun.com/docs/runtime/yaml).

## Boundaries

Research results are scoped to their reported models, repositories, and harnesses. Prompt structure doesn't prove behavioral enforcement, graph impact isn't a substitute for repository tests, and no cited benchmark percentage is presented as a Forge performance guarantee.

Agents and contributors working in this repository should use [AGENTS.md](../AGENTS.md) as the owner map and [CONTRIBUTING.md](../CONTRIBUTING.md) for instruction-layer change process.
